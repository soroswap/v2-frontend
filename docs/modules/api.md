# API Module (server-side BFF)

> **Living document.** Read this before modifying the module. Update it in the same change whenever the module's behavior, endpoints, files, or dependencies change.

**Source:** `src/app/api/`, `src/shared/lib/server/`, `src/shared/lib/environmentVars.ts` · **Last verified:** 2026-09-10

## Purpose

Every call this app makes to the Soroswap API and the DeFindex API goes through these Next.js route handlers. They exist so `SOROSWAP_API_KEY` and `DEFINDEX_API_KEY` never reach the browser: the SDK clients are constructed server-side and the browser only ever talks to same-origin `/api/*`. Change a route signature here and the feature hooks in `src/features/*` break immediately, because they hand-roll `fetch` calls against these exact paths and headers.

## Key methods

- **`soroswapClient`** (`src/shared/lib/server/soroswapClient.ts:4`) constructed at module scope with `{ apiKey, baseUrl, defaultNetwork }` from `SOROSWAP` in `environmentVars.ts:75-82`. Because it is module scope, a missing key does not fail at boot, it fails on the first upstream call.
- **`defindexClient`** (`src/shared/lib/server/defindexClient.ts:4`) constructed with `{ apiKey, baseUrl }` only. Network is passed per call instead, which is why every earn route needs a `network` header.
- **`getSodaxClient()`** (`src/shared/lib/server/sodaxClient.ts:15-31`) builds its `SwapsApi` singleton lazily, not at module scope like `soroswapClient`/`defindexClient` above, specifically so a missing `SODAX_SWAPS_API_URL` throws on the first request instead of crashing `next build` (`:17-21`). It attaches `x-api-key` only when `SODAX_API_KEY` is set (`:22-28`).
- **`sodaxOriginGuard`** (`src/shared/lib/server/sodaxClient.ts:88-102`) accepts a request when the parsed Origin/Referer host either matches `ALLOWED_ORIGINS` (`isAllowedOrigin`, `:51-76`) or equals the request's own host — read from `x-forwarded-host` first, then `host` (`:91-92`). The same-origin branch exists so a Vercel preview deployment (`<project>-git-<branch>-<team>.vercel.app`, a fresh string per branch) is never mistaken for a forbidden origin; see Gotchas.
- **`sodaxErrorResponse`** (`src/shared/lib/server/sodaxClient.ts:162-193`) maps any thrown value to `{ code, message }` only — never the upstream `SwapsApiErrorContext` (endpoint/path, raw upstream body, valibot `issues`). For `HTTP_ERROR` the message is the upstream body's own `message` when it sent one (`httpErrorMessage`, `:137-151`), else a generic string by status class; every other `SwapsApiError` code keeps its SDK message; a non-`SwapsApiError` failure gets a fixed `"Unexpected error while talking to SODAX"`. The full error, context included, is always `console.error`'d server-side first. Not used by `/api/sodax/send`, which builds its own responses.
- **`parseSodaxBody` / `parseSodaxQuery`** (`src/shared/lib/server/sodaxSchemas.ts:173-217`) validate a JSON body or a query-string object against a Zod schema and return either `{ data }` or a ready-to-return `{ error }` 400 `SODAX_ERROR_PARAM` response (first Zod issue's path + message; `parseSodaxBody` also catches a non-JSON body). Every validated route builds its upstream call from `data` only, never the raw input.
- **`fetchMainnetAssetListWithRetry`** (`src/app/api/tokens/route.ts:60`) retries up to `MAX_RETRIES = 3` with a fixed `RETRY_DELAY_MS = 2000` delay, but only when the error looks like a rate limit (`:79-83`). This is the only retry logic on the server side.
- **`fetchTestnetAssetList`** (`src/app/api/tokens/route.ts:36`) bypasses the SDK and hits the unauthenticated public endpoint `${SOROSWAP_API_URL}/api/tokens`, then picks the entry whose `network === "testnet"`.
- **`envVars`** (`src/shared/lib/environmentVars.ts:40`) derives everything from a single `NEXT_PUBLIC_ENV` value: wallet network, RPC URL, Horizon URL, network passphrase, and the hardcoded Soroswap router contract address per network (`:65-68`).

## Gotchas & invariants

- **The origin gate is not applied uniformly.** Every Soroswap route and `/api/earn/send` check `ALLOWED_ORIGINS` (`src/shared/lib/server/constants.ts:1`) against the `origin` or `referer` header and return 403 otherwise. The five other earn routes (`vaultInfo`, `vaultBalance`, `deposit`, `withdraw`, `withdraw/share`) do **not** import `ALLOWED_ORIGINS` at all and are open to any caller. Match the existing pattern when adding an earn route.
- The check is a substring match (`origin.includes(allowed)`), and `".soroswap.finance"` is one of the entries, so any origin containing that string passes.
- **Earn routes read their inputs from headers, including POSTs.** `src/features/earn/hooks/useVaultDeposit.ts:38-50` sends `vaultId`/`amount`/`caller`/`slippageBps` in the JSON body instead, which the route never reads. That hook has no consumer anywhere in `src/`, so the mismatch is latent, not a live bug.
- **The `network` guard is not on every route.** Eleven of the seventeen handlers guard `if (!network)` and report `Missing "network" query parameter`; `/api/balance` and the five earn data routes have no such guard. Where it exists the branch is effectively unreachable anyway: `network` is a build-time constant from `NEXT_PUBLIC_ENV` (`src/shared/lib/environmentVars.ts:44`), never a query parameter, so the message is misleading.
- `src/app/api/price/route.ts:103` returns `{ status: 500 | error.statusCode }`. That is a bitwise OR, not a fallback, so the status is garbage on the error path. Do not copy this pattern.
- **There is no server-side cache anywhere in `src/app/api/`, except `/api/sodax/tokens` and `/api/sodax/price`.** `tokens` keeps an in-memory `Map` keyed by the `chain` param with a 1 hour TTL (`src/app/api/sodax/tokens/route.ts:15-16,40-43`), because token listings change rarely and the client-side SWR cache does not survive a page reload. `price` keeps the same shape of cache keyed by `contract`, 120 s TTL (`src/app/api/sodax/price/route.ts:33-37,62-65,88-89`) — the USD-price probe quote is identical for every visitor of a given asset, so without a cache N concurrent visitors is N live solver quotes per refresh interval. Everywhere else, all caching is client-side SWR deduping in the feature hooks. Earlier documentation claimed a 3 minute in-memory price cache on `/api/price` (the Soroswap one); no such code exists there.
- **The SODAX routes use a different, stricter origin check than everything above, plus a same-origin fallback the others don't have.** `sodaxOriginGuard` (`src/shared/lib/server/sodaxClient.ts:88-102`) parses `Origin`/`Referer` with `new URL()` and accepts the request when the resulting **host** either matches `ALLOWED_ORIGINS` — exact match, or dot-suffix match for `.soroswap.finance`-style entries (`isAllowedOrigin`, `:51-76`) — or equals the request's own host, read from `x-forwarded-host` then `host` (`:91-92`). This is stricter than the substring check (`origin.includes(allowed)`) the Soroswap/earn routes above use inline: the SODAX routes include a direct-to-RPC broadcast endpoint, where the substring check would let `https://evil.com/?x=app.soroswap.finance` through. The same-origin fallback was added after the anchored check shipped without it: a Vercel preview host (`<project>-git-<branch>-<team>.vercel.app`, a fresh string per branch) never equals or suffix-matches a fixed `ALLOWED_ORIGINS` entry, so every `/api/sodax/*` route 403'd on every preview deployment — the exact URLs reviewers open — with `useSodaxAvailability` silently flipping the feature off client-side (no visible error). Comparing against the request's own host fixes every current and future deployment without widening the allow-list, and grants nothing a same-origin `fetch` couldn't already do.
- **`/api/sodax/send` does not use `soroswapClient.send` and cannot.** The generic `/api/send` proxies Soroswap's send API, which rejects Soroban transactions that don't touch a Soroswap contract — every SODAX intent invocation does (`src/app/api/sodax/send/route.ts:63-66`). So `/api/sodax/send` submits directly to `rpc.Server(STELLAR.RPC_URL, { timeout: 15_000 })` instead (`:135,140`), and allowlists only the operation types a SODAX swap legitimately needs (`invokeHostFunction`, `extendFootprintTtl`, `restoreFootprint`, `changeTrust`, `:26-31`) so it can't become a general-purpose broadcast relay.
- **`/api/sodax/send`'s error contract tells the client whether a retry is safe** (`src/app/api/sodax/send/route.ts:71-74`): 400/503 `SODAX_ERROR_SUBMIT` means the Stellar network definitively did **not** take the transaction — rejected (`:168-178`, e.g. expired) or `TRY_AGAIN_LATER` congestion (`:180-190`) — safe to retry. 502 `SODAX_ERROR_BROADCAST_UNKNOWN` with `context.txHash` (`:157-165`) means `sendTransaction` itself threw (RPC timeout, proxy error, socket reset) and the route could not confirm within a 6 s post-failure probe (`UNKNOWN_STATE_PROBE_MS`, `:16`) whether stellar-core had already accepted it — **not** safe to retry; the caller should track the given hash instead. In every case the transaction hash is computed locally from the signed envelope before submission (`transaction.hash()`, `:134`), so it is known even when the submit call fails outright. A confirmed accept (`PENDING`/`DUPLICATE`) is followed by up to 30 s of `getTransaction` polling (`probeTransaction`, `:36-58`, `CONFIRM_TIMEOUT_MS`, `:10`) before answering `confirmed: false` if it's still not in a ledger. Each RPC call is bounded by `withTimeout` (`RPC_TIMEOUT_MS = 15_000`, `:22-46`) because `rpc.Server` ignores its typed `timeout` option at runtime, so the route's worst case is ~15 s submit + 30 s confirm + one poll interval. The client's own request timeout (`SODAX_BROADCAST_TIMEOUT_MS = 55_000`, `src/features/sodax/constants/sodax.ts:35`) must stay strictly larger than that, inside `maxDuration = 60` (`:7`) — that mismatch was finding 1/2 in the verification round; see `git show` on this route's "never invite a retry once the intent transaction may be on-chain" commit for the full history.
- **`quote`, `allowance`, `approve`, `intents`, `submit`, and `submit/status` pin their request to exactly what this app ever sends** — this is an invariant, not incidental validation (`src/shared/lib/server/sodaxSchemas.ts`). Every `*ChainKey` field must equal `SODAX_STELLAR_CHAIN_KEY` (`"stellar"`) exactly (`chainKey`, `:55`); every token address must be a `SODAX_ASSETS_BY_CONTRACT` registry entry or one of the two `SODAX_COUNTERPART_CONTRACTS` (XLM, USDC) (`sodaxToken`, `:63-72`); `allowance`/`approve`/`intents` require `srcAddress === dstAddress` (`:104-107`) and `allowPartialFill === false` (`:100`) — every call site in `useSodaxSwap.tsx` already sends exactly that, so this rejects nothing the app itself does. Each route calls `getSodaxClient()` with the **parsed** result only (e.g. `client.getQuote(parsed.data)`), never the raw body — Zod's default object mode silently strips unknown keys, so a caller cannot graft `partnerFee`, `hook`, `solver`, or `data` onto the upstream request. A validation failure is 400 `SODAX_ERROR_PARAM` with the first issue's path + message, before any upstream call; a non-JSON body gets the same 400 instead of a 500 with the JSON parser's raw error text. `submit/route.ts:34-36` casts the validated body at the `submitTx` call: the SDK types `SubmitTxRequestV2.intent` as `IntentRequestV2`, whose numeric fields are `bigint`, but this route only ever sees the browser's decimal-string wire shape, and the SDK's own `submitTx` (`serializeIntentRequest`) passes any non-bigint field through unchanged — so the cast reconciles a type that predates a JSON-only caller, not a real runtime mismatch.
- `/api/tokens` prepends XLM to the asset list from `xlmTokenList` when it is not already present (`src/app/api/tokens/route.ts:152-161`). The fallback token list contains only XLM per network, not a large curated list (`src/shared/lib/constants/tokenList.ts`).
- Amounts sent to `/api/earn/deposit` are cast with `Number(amount)` (`src/app/api/earn/deposit/route.ts:44`) with a TODO noting the unit conversion is unfinished. Callers already pass the smallest-unit integer (`src/features/earn/hooks/useEarnVault.ts:139-142`).
- `NEXT_PUBLIC_POSTHOG_HOST` appears in `.env.example:12` but is never read anywhere in `src/`; the PostHog host is hardcoded (`src/shared/providers/PostHogProvider.tsx:11-12`).

- **`/api/sodax/price` caches "no route" answers too** (`src/app/api/sodax/price/route.ts:96-104`): a 422 from the solver is stored as `usdPrice: null` for the same 120 s TTL as a real price, so the assets most likely to have no probe route do not become a live solver quote per visitor.

## Testing

No test framework, test script, or test files exist in this repo (`package.json:5-10` defines only `dev`, `build`, `start`, `lint`). Verification today is `pnpm lint` plus manual exercise against testnet and mainnet.
